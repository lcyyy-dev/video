# 文字样式与剪映草稿兼容规范

本文记录 OpenFilm 当前导出器的文字数据约定、剪映草稿字段映射、资源要求和验证方法，供样式库建设、AI 选样式及后续开发使用。

这是一份项目兼容规范，不是剪映官方公开格式标准。字段依据当前实现、自动测试和实际导出文件整理；“已输出对应字段”不代表所有客户端版本均能完全还原视觉效果。剪映与 CapCut 的客户端验证结果分别记录，不互相代替。

## 机器可读入口

生成时优先读取 `packages/openfilm/src/text-style-compatibility.json`，而不是仅从本文提取规则。该文件包含版本、目标软件、可用外观字段、取值约束、单位、草稿映射、字体依赖、关键帧能力、回退条件及验证状态。

AI 可以执行 `openfilm text-styles rules` 获取规则、`openfilm text-styles list` 获取预设、`openfilm text-styles show <id>` 获取单个预设；也可调用 `openfilm/text-styles` 的 `getTextStyleCompatibility()`。当前样式校验从该 JSON 读取允许字段和必填字段，实际草稿导出通过同一份回退规则决定是否渲染。

JSON 中的换算表达式用于描述和查询，不作为脚本执行；具体数值转换仍由导出器负责，复杂取值校验仍复用文字校验器。文档提供背景和验证方法，结构化规则供程序与 AI 直接使用，二者需要同步维护。

## 1. 基本原则

样式是否原生可编辑，取决于属性和资源是否被目标剪辑软件识别，不取决于这个组合是否出现在剪映的预设列表里。自定义“蓝色填充 + 黑色偏移阴影”无需先成为剪映内置预设。

```text
样式库 JSON：可复用外观参数
  → AI 选择样式并应用到具体文案
  → 工程文字数据：内容、布局、样式及关键帧
  → HTML：OpenFilm 预览载体，嵌入结构化文字 JSON
  → 导出器：转换为剪映 text 轨道与 materials.texts
```

AI 不直接拼装整份剪映草稿，也不随意生成剪映效果资源 ID。样式先遵守 OpenFilm 的数据约定，再由同一个导出器做目标格式转换。

## 2. 当前数据约定

### 2.1 样式库

当前库格式为 `{ version: 1, presets: [...] }`。每个预设必须有 `id`、正整数 `version`、`name`、`description` 和 `style`。ID 在库内唯一，使用小写字母开头、后接小写字母、数字或连字符。

当前 `style` 仅接受以下外观字段：

```json
{
  "fontFamily": "sans-serif",
  "fontSize": 80,
  "color": "#008cff",
  "bold": true,
  "italic": false,
  "underline": false,
  "stroke": { "color": "#000000", "width": 2 },
  "shadow": { "color": "#000000", "opacity": 1, "blur": 1, "x": 5, "y": 6 }
}
```

其中 `fontSize` 必填，单位为预览像素；当前内置预设以 1080 像素宽画布为参考，不自动按画幅缩放。可另传 `fontPath` 指定目标电脑上的字体文件。

颜色必须为 `#RRGGBB`；字号大于零；描边宽度和阴影模糊不小于零；阴影透明度在 0～1 之间。未知字段和不合法值必须报错，不能直接带进草稿。

用途标签、兼容等级、字体资源清单等是后续库管理需求，当前预设校验器尚不接受这些字段。引入时需要同步更新 schema、校验和测试，不能仅往现有 JSON 增加字段。

### 2.2 工程中的文字

`TextPage` 保存 `version: 1`、画布 `width/height`、源页面 `duration` 和非空 `texts`。每个文字对象至少有 `text`、中心点 `x/y`、`fontSize`。布局、透明度、缩放及动画属于文字对象，不属于当前基础样式预设。

应用预设后，把完整解析结果保存进工程。预设 ID 和版本如需溯源，保存在制作计划中，不直接塞进现有 `TextItem`。旧工程不随样式库更新自动改变。

当前 `applyTextStyle` 会替换旧外观，并清除旧的逐字格式，让 `runs` 继承新样式；保留内容、布局及关键帧。需要重点词样式时，在应用预设后再设置对应 `runs`。

## 3. 原生文字的草稿结构

- `draft_info.json` 和 `draft_content.json`：当前导出器写入相同的工程内容，以适配不同读取入口。
- `draft_meta_info.json`：草稿名称、位置及媒体库元信息，不承担文字外观定义。
- `materials.texts[]`：文字素材，其中 `content` 是一个 JSON 字符串，解析后包含 `text` 和 `styles`。
- `tracks[]` 中 `type: "text"`：独立文字轨道。每个 `segment.material_id` 引用文字素材 ID。
- `segment.target_timerange`：显示起点及持续时间，单位为微秒。当前原生文字 `source_timerange` 为 `null`。
- `media/`：需要复制的音视频或回退素材；纯原生文字工程不要求存在文字 MOV 或媒体文件。

一段富文本可以包含多个范围样式，仍是一个文字对象和一个片段。顺序、非重叠的文字可复用同一轨道；同时出现的独立文字对象可能需要不同轨道。

## 4. 当前字段映射

下表记录导出器的现行规则。涉及比率或换算的数值按当前实现处理，不应理解为官方通用换算公式。

| OpenFilm 属性 | 剪映草稿位置 / 转换 | 约束与验证重点 |
| --- | --- | --- |
| `text` | `JSON.parse(material.content).text` | 保存真实文案，不能只保存图片或视频路径 |
| `runs` | `content.styles[].range`、`is_rich_text` | 范围是 UTF-16 `[start, end]`，不是字符数量或字节数；拼接必须完整覆盖文案 |
| `fontSize` | `styles[].size`、`font_size` | 当前 `fontSize × 6 / 48`；需目视核对实际大小 |
| `fontFamily` | `styles[].font.name`、`font_name` | 是字体名称，不是花字资源 ID；是否可用取决于目标环境 |
| `fontPath` | `styles[].font.path`、`font_path` | 必须能在目标电脑解析；当前不会自动打包字体文件 |
| `color` | `styles[].fill.content.solid.color`、`text_color` | 填充色 RGB 归一化到 0～1；素材级颜色写成 `#RRGGBBFF` |
| `bold / italic / underline` | `styles[]` 同名属性 | 字体字重或合成效果可能影响视觉一致性 |
| `stroke` | `styles[].strokes[]`、`border_color/border_width` | 描边宽度当前除以该范围字号；零宽度与不同字重需要检查 |
| `shadow` | `styles[].shadows[]` 及素材级 `shadow_*` | 距离为 `hypot(x,y)`，角度为 `atan2(y,x)` 转角度；`diffuse = blur/fontSize/6`，需核对方向与软硬程度 |
| `align` | `alignment / text_alignment` | 左、中、右分别为 0、1、2 |
| `width` | `line_max_width`、`force_apply_line_max_width` | 当前除以页面宽度；浏览器与剪映换行结果可能不同 |
| `lineHeight` | `line_spacing` | 显式值减 1；未设置时当前使用 0.02，预览默认行高则为 1.25，不能假定默认排版完全一致 |
| `letterSpacing` | `letter_spacing` | 当前除以对象字号 |
| `opacity` | `global_alpha` | 静态透明度可写入；透明度动画另见回退条件 |
| `x / y` | `segment.clip.transform` | 中心坐标归一化：`x'=2×(x/W−0.5)`、`y'=2×(0.5−y/H)`，注意 Y 轴方向 |
| `scale` | `segment.clip.scale`、`uniform_scale` | 统一缩放；不作为预设字号的替代 |
| 位置 / 缩放关键帧 | `common_keyframes` | 类型为 `KFTypePositionX`、`KFTypePositionY`、`UNIFORM_SCALE`，当前线性插值并补裁剪边界采样 |

富文本的每个范围可覆盖字号、颜色、加粗、斜体、下划线、描边，其余继承对象属性；当前不支持在 `runs` 中单独指定字体、阴影或动画。不能因为草稿格式可能支持某字段，就认定 OpenFilm 已支持。

## 5. 字体、花字与资源依赖

### 普通字体与参数样式

名称、字号、颜色、描边、阴影等可以由本地 JSON 定义，不需要剪映预设 ID。字体文件仍是独立依赖：本机可预览，不代表目标剪映电脑也有字体；路径必须针对目标系统处理，不能把 WSL 路径当作 Windows 字体路径。

如果使用默认 `sans-serif`，只能保证有系统回退，不能保证 OpenFilm 与剪映选中同一个字体。要追求视觉一致，需明确字体及可用字重，并检查中文、数字和符号是否有缺字。

### 特殊花字、气泡及装饰模板

此类效果可能依赖效果定义、纹理、图片、字体或客户端内的资源解析。不能把一个名字、`effect_id` 或 `resource_id` 当作完整样式，也不能假定剪映本地缓存可以直接作为 OpenFilm 可分发的通用样式库。

当前基础样式库和导出器没有实现通用花字资源导入。接入前必须拿到实际样本，确认依赖、目标版本及引用方式；分别验证 OpenFilm 预览、剪映显示、原生文字修改和资源缺失时的行为。只在剪映能显示、OpenFilm 无法预览的样式要单独标明。

## 6. 原生导出与回退边界

当前结构化文字只有在以下条件满足时，才进入原生导出：

1. HTML 中存在有效的 `openfilm-text` JSON，能通过现有校验。
2. 文字页面尺寸与工程画布一致。
3. 没有片段级 CSS、class、box、fade 或变速覆盖。
4. 没有需要渲染保留的 Studio 元素编辑覆盖。
5. 没有文字 `opacity` 关键帧。

不满足条件时，现有导出流程会将页面渲染成媒体，并在 `native-text-report.json` 中记录结构化页面的 `native/rendered` 结果及原因。任意 HTML 页面也会走媒体渲染，不能仅凭页面看起来是文字就认定为原生对象。XML 导出仍使用渲染页面。

未知或不合法的结构化字段由校验器报错，不保证自动渲染兜底。新增效果必须明确“校验拒绝”“可预览但需渲染”或“可原生转换”，不能静默忽略属性。

## 7. 兼容状态与样式入库要求

后续样式目录需要维护以下状态；目前它们属于规范要求，尚未作为字段接入预设 JSON：

| 状态 | 含义 |
| --- | --- |
| 原生字段已验证 | 实际导出文件存在正确文字、样式字段和时间引用，未生成文字视频 |
| 客户端已验证 | 在记录的剪映 / CapCut 版本中打开，并检查外观、改字及改时间；不能仅通过 JSON 检查得到此状态 |
| 依赖资源 | 需明确字体或效果资源；在这些依赖满足前，不能承诺一致显示 |
| 需预渲染 | 效果保留为媒体，无法原生修改文字；必须展示回退原因 |
| 未支持 | 尚无可靠转换或依赖不完整，不能交给 AI 当作可用原生样式选择 |

同一个样式可以同时有“原生字段已验证”和“依赖资源”状态。兼容记录至少包含预设 ID/版本、导出器代码版本、目标软件及实际版本、操作系统、字体、验证状态、已知差异和测试样片位置。草稿中的 `platform.app_version` 等固定值只是导出元数据，不代表实际测试过那个客户端版本。

入库验证应覆盖短句、长句、中文、数字、标点、换行和 emoji，检查原生文字范围、字体、描边、阴影及裁剪边界。至少执行一次修改文字内容和时间后保存、重新打开，确认不是仅初次可见。

## 8. 当前证据与后续检查

- `src/text-styles.test.mjs`：样式 JSON 校验、复制隔离、样式切换及文字页面数据往返。
- `studio/server/jianying.test.mjs`：内置预设映射到 Jianying / CapCut 原生文字字段，无对应文字 MOV。
- 本地实际导出记录 `.dev/text-style-library/export-check.json`：三种基础预设生成三个原生文字对象，顺序位于一条文字轨，视频素材数量为零；示例工程和草稿保留在同目录下。
- 以上实际导出记录证明的是结构与原生字段，不等于三种预设均已完成目标剪映版本的视觉对照。此前用户确认草稿可打开、文字可编辑，也不能替代新增效果的逐类验证。
- 后续“文字格式链路验证”15 秒样片使用大字号、不同字体、颜色、粗描边和阴影，用户已确认能够显示文字效果。该结果记为一次客户端效果确认；未记录精确客户端版本，尚不等于所有属性、预设及版本均已完成视觉一致性认证。

涉及字段映射的变更，需同步修改本规范、格式说明和相关测试。新增样式可以复用已验证的属性组合，不必为每个颜色组合开发新导出逻辑；新增一种效果属性或资源类型则必须重新验证兼容性。
