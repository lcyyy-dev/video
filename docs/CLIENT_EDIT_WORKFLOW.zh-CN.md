# 客户端模板剪辑流程

此分支只提供桌面客户端。`pnpm dev` 和 `pnpm dev:desktop` 均启动 Electron；`pnpm build` 只构建客户端窗口。独立浏览器入口、独立 UI 构建、网页版开发服务器和网页版文件夹浏览器已移除。共用编辑器源码、本地 API、CLI 和用于预览/导出的无界面 Chromium 仍是客户端所需的引擎。

## 使用流程

1. 打开项目，将视频、图片或音频拖到右侧输入框上方的“上传素材”区域，也可以点击该区域多选文件。区域会显示缩略图、添加状态和数量；移除附件不会删除已经导入项目的素材。随后在“剪辑模板”中选择广告素材、口播、文案二创或直播切片，并配置对应的标题、正文和补充要求。
2. 点击“保存并输入需求”。主进程保存到项目 `.film/edit-template.json`，关闭向导并将焦点移回输入框。
3. 添加素材或引用已有素材，输入自然语言需求，例如“用这些素材生成一条 15 秒门店广告”。无需输入 skill 名称或固定命令。
4. 主进程读取项目模板，根据固定映射加载应用自带的 skill。视频请求先经过范围检查，Codex 只在当前项目的 `workspace-write` 沙箱中工作，项目内的命令和写入仍由原生沙箱执行；项目外的设置、账号和文件写入会被拦截。日志记录模板配置和 skill 名称。
5. Codex 返回严格的结构化剪辑计划，原生执行器验证素材编号、时段、轨道、字幕及锁定内容后更新 `film.html` 和生成的原生文字页面。模型不能运行命令、生成可执行 HTML 或任意文件补丁。默认只更新工程；明确要求导出时才进入原生导出队列，未指定格式时导出剪映草稿，明确要求 MP4 时才导出 MP4。
6. 继续输入“第二段换镜头”“不要标题”等需求，仍经过同一固定路由。执行中的追加需求排队后重新检查，不直接注入运行中的规划。修改前检查工程版本，避免覆盖分析期间的手工操作。
7. 点击右侧顶部“导出剪映草稿”。Windows 和 macOS 初次预填剪映默认草稿目录，仍可选择文件夹或输入完整路径；此后记住所选位置。Linux 没有剪映原生默认目录，使用普通导出目录作为后备。导出前等待编辑保存，输出独立草稿文件夹及素材，保留视频、音频和支持的原生文字轨道；重复导出自动使用新名称。窗口显示进度、失败详情和实际保存位置，也可打开文件夹。

上传的每个文件会显示稳定的素材编号、文件名和预览。点击“描述此素材”，输入框会自动插入绑定该文件的标签，随后直接输入“这段放开头，保留原声”等要求即可；不必记文件名或使用 `@`。可继续点击其他素材分别写要求，整体需求会保留。同名文件按实际导入路径分别绑定，移除附件不重新编号，发送时同时携带编号与文件路径。

素材添加后，拖放入口收为紧凑条，输入区以两列网格完整展示前 4 个素材。“展开素材库”或“查看全部”打开独立的大缩略图窗口，支持按文件名或素材编号搜索、预览、继续选择或拖入素材，以及移除附件。点击“描述此素材”会关闭素材库并返回输入框；这些操作只管理本次需求的附件，不删除项目素材文件。`.dev/material-gallery/acceptance.json` 记录 8 个素材和 1280×720 窗口的真实客户端验收。

缺少素材、文案或录音时，继续可完成的分析并说明缺失内容；不将空项目或占位音频宣称为成片。配音使用提供的录音，或明确要求的本地模拟。项目文件和模板配置均保存在本机。

## 操作范围控制

项目会话使用 `workspace-write` 沙箱和自动执行策略。模板视频请求采用固定短流程：读取素材、读取对应 skill、读取模板原文、逐句生成音频、拼接时间线、做一次最终检查并结束。不会额外研究、改写文案、添加素材、导出或清理无关文件，除非用户明确提出；项目外的设置、账号和文件仍受边界保护。

## 固定路由

| 模板类型 | skill | 状态 |
| --- | --- | --- |
| 广告素材 `ad` | `ad-editing` | 已接入 |
| 口播 `talk` | `talk-editing` | 已接入 |
| 文案二创 `copy` | `copy-rewrite` | 已接入 |
| 直播切片 `live` | `live-clips` | 已接入 |

路由定义在 `apps/desktop/src/edit-template.mjs`。不通过模型判断、不根据用户话术切换 skill，也不静默回退到其他模板。模板配置损坏或 skill 不可读取时，阻止发送并显示错误。

模板保存通过受信任的客户端 IPC，限制在已登记项目中。配置不再使用 `localStorage`，旧的页面临时配置不自动应用，需要在客户端重新保存一次。重启后按项目加载配置；关闭向导而未保存的修改不生效。

## 验证

`apps/desktop/src/edit-workflow.test.mjs` 验证本地保存与项目隔离、IPC 来源/路径限制、固定 skill 加载、缺失 skill 阻断，以及正常发送、执行中追加、后续修改和日志。Agent 传输使用测试替身，避免依赖账号与模型输出。

`packages/openfilm/studio/server/server.test.mjs` 验证无独立网页、无网页版目录浏览 API、旧浏览器打开参数不生效，以及项目可导航到桌面窗口。

实际成片质量仍需使用真实素材检查镜头语义、配音、文字布局及导出结果；传输链路测试不能代替成片验收。权限结构和验收详见 [视频聊天权限边界](VIDEO_CHAT_SECURITY.zh-CN.md)。

## 历史流程验收（权限收敛前）

客户端 137 项测试、引擎/CLI 47 项测试、实际 MP4 导出测试通过；客户端与共用编辑器类型检查、客户端构建通过。实际 Electron 窗口验证了模板保存、重载恢复及保存后返回输入框。

重新登录后定位并修复了会话初始化超时：客户端启动器和子进程环境此前丢失桌面网络代理，导致 `workspace routing discovery timed out`。现在保留现有 HTTP/HTTPS/ALL/NO_PROXY 设置及其小写形式；登录 shell 的显式设置覆盖继承值，包括显式禁用代理。此修改不透传父级 agent 的认证与会话变量。已用实际 Gmail 登录会话确认 Codex 能创建会话并开始固定 skill 剪辑。

真实客户端端到端验收已通过，使用独立测试项目 `.dev/client-flow`（不纳入 Git）：

- 使用当前已登录的 Gmail / ChatGPT Plus 账号，输入自然语言需求，主进程固定加载 `ad-editing`。实际会话 `local-hppv50lj8z` 完成广告素材分析、文字配置、工程创建、检查和 MP4 导出。
