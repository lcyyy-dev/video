# 客户端动画性能

目标是在正常 Windows 桌面环境的 60 Hz 显示器上保持接近 60 FPS：每帧预算约 16.7 ms，避免输入过程中出现超过 50 ms 的主线程长任务。此目标针对应用交互动画；视频解码和媒体文件本身的帧率应分别检查。

## 本次优化

- Stepper 保留原有的高度补间（560 ms）、内容滑动（560 ms）、淡入（420 ms）、退出与完成勾选动画。导航高亮通过 FLIP 位移和缩放实现原来的尺寸/位置过渡，不逐帧修改宽高。宽度未变化时不重复测量导航，忽略 ResizeObserver 的初始重复通知，防止过渡刚开始就被取消。
- 减少弹窗背景的实时滤镜叠加；深色遮罩和卡片的边框、高光、阴影仍保留。弹窗本身通过透明度和位移过渡进入。
- Studio 和聊天共用一个聚光卡片实现。渐变纹理按配置缓存，通过位移移动光晕；边框只更新光斑位置。尺寸测量按布局变化失效，离屏、后台和静止状态停止动画循环。
- 分隔线把高频指针输入合并为每个显示帧一次，松开时同步提交最后输入。拖动中的本地存储改为延迟保存，离开页面时刷入。
- 音量表缓存主题颜色和渐变，避免播放时每帧读取计算样式和重复创建渐变；显示器缩放比例改变时会更新缓存。
- 聊天宽度已经到达边界时，不再重复发布相同布局。

这些修改使用 Chromium 的标准 CSS、Web Animations 和 requestAnimationFrame，不依赖 WSL、显卡型号或修改 Windows 全局驱动配置。Electron 默认的 Windows 硬件加速路径保持启用。

## Windows 验证

在 Windows 上启动客户端并带本机调试端口，例如：

```powershell
OpenFilm.exe --remote-debugging-port=9333
```

在有项目源码及依赖的目录执行：

```powershell
pnpm --filter @openfilm/desktop perf:animations --assert --output=animation-performance.json
```

开发版也可用 `pnpm --filter @openfilm/desktop start --remote-debugging-port=9333` 启动。`--reload` 用于加载刚构建的开发页面；它会重新加载当前项目，先保存编辑中的模板配置。

脚本测量空闲编辑器、卡片悬停、模板打开、完整步骤切换，记录 FPS、帧间隔 p50/p95、超过 33 ms 的帧、长任务及实际 GPU 状态。`--assert` 在平均帧率低于 55 FPS、p95 超过 20 ms、出现主线程长任务、页面错误或横向溢出时返回失败；标准针对 60 Hz 屏幕。`--cpu=4` 可额外做主线程压力测试，其结果单独评估，不代替正常环境验收。

除自动采样外，检查以下操作：

1. 来回切换所有步骤，确认高亮滑动、卡片高度变化、淡入淡出都完整存在。
2. 在切换中快速返回前一步，检查没有残留内容、跳闪或丢失输入。
3. 拖动预览、检查器、时间线和聊天区的交界，松开后保持最后位置，并恢复普通光标。
4. 播放项目、拖动时间线及切换深浅主题，检查电平表、播放头和字体缩放。
5. 空闲或切到后台后，装饰性动画不应持续消耗主线程。

本地软件渲染环境的性能数据只能用于同环境前后对照，不能声称已经代替 Windows 实机验收。Windows 报告还应检查 `gpu_compositing` 与 `rasterization` 是否启用；应用动画和系统驱动回退需分别归因。
