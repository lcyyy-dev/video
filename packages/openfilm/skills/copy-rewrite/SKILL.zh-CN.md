# 文案二创

用户明确要求更短、更口语或更有吸引力时，才对已有文案进行对应方向的改写。

## 锁定原始文案

读取 OpenFilm 手册和工程。保存 `copy-plan.json`，记录原文、改写方向、逐句对应关系、必须保留的事实、镜头范围、音频状态和检查结果。

原始文案是事实来源。不能增加价格、保证、地点、日期、评价或产品能力。表达有歧义时保持谨慎并报告问题。

如果模板中已经填写的是最终文案，必须逐字保留，不能压缩、概括、改写、补写或删字。只有用户在当前需求中明确要求改写时，才按指定方向生成新的口播稿；原文和最终稿必须分开保存，不能混在一起。

## 视频节奏

使用 `openfilm look` 检查全部素材，把每个脚本句子匹配到有意义的镜头。优先使用提供的录音；没有录音时，只有用户明确要求才使用本地模拟旁白，否则保留无旁白的文字剪辑。测量每个音频文件后再确定镜头和字幕边界。

保持语句完整，在自然停顿处剪切。字幕必须来自最终确认的口播稿。使用本地文字样式库和结构化文字页面，保证标题和字幕可编辑；如果模板的 `textStyleIds` 有内容，只能从这些样式 ID 中选择，列表为空时才使用元素库自动组合。

## 检查和交付

检查原文事实、发音、音频时长、镜头与句子的对应关系，以及字幕安全区。保留手工修改和锁定片段。修改后运行 `openfilm look`。只有用户要求时才导出 MP4 或剪映草稿；否则保留可编辑工程。报告缺失音频、未确认事实、不支持的样式和仍未完成的输出。
