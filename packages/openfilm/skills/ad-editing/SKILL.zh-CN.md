# 广告素材剪辑

使用相关镜头和可编辑的画面文字表达提供的广告信息。镜头、文字和旁白可以分别确定边界，但必须保留用户提供的事实、素材和文案。

## 执行顺序

普通模板生成请求只执行短流程：读取素材、读取本 skill、读取模板原文、按朗读开关生成豆包旁白或保留视频原声、拼接时间线，然后直接汇报结果；不自动追加任何预览或检查。不增加调研、备用方案、无关清理或导出，除非用户明确要求。

### 文案朗读可选项

广告不再划分广告形式，统一使用本流程。内容中的 narration 是“文案朗读”开关，默认不勾选。不勾选时保留视频原声，不生成配音；勾选时调用会话提供的原生 TTS 接口，使用 seed-tts-2.0 合成正文全文，生成真实旁白后再编排时间线。按 .film/narration.json 的真实时长和路径插入独立 audio 片段，默认压低视频原声至 0.15。不设置独立录音输入或复用录音步骤。

## 广告文字版式

广告使用视频原声时，下面的字段映射是强制规则，除非用户明确指定其他样式：

- `titleText`：顶部主标题。必须根据实际文字宽度自动缩小字号，必要时可降到约 42px；保持 `white-space: nowrap`，完整标题只占一行，不能插入换行或让浏览器自动换行。
- `subtitleTexts[]`：按顺序排列的多条核心卖点。数组中的每个元素都对应一个独立输入框和一个独立文字元素，必须逐条保留，不能合并成一段。
- `bodyText`：按句拆分的强调句或说明句，必须保留每个字符和句子顺序。
- `locationText`：单独的地点标签。

字段中有多个句子时，可以拆成多个按句显示的文字片段，但不得改写文案。不能把多句正文塞进一个过大的段落中。

1. **顶部主标题**：上方单行。从元素库抽取高对比彩色字组合，并按实际文字宽度缩小字号。先从 78–112px 开始，保证完整标题单行显示且清晰可读。
2. **核心卖点**：从元素库抽取粗体高对比组合。原生文字页面不要自行添加蓝色条幅、圆角框或白底标签。画布字号 68–100px。
3. **强调句**：从元素库抽取黄色、橙色或红色文字与描边组合。画布字号 58–88px。
4. **说明句**：从元素库抽取白色、黄色或红色文字与描边组合。画布字号 48–78px。
5. **家长评价/结论句**：只有模板提供对应文案时才抽取红色或白色文字与深色描边组合。画布字号 48–76px。
6. **地点**：放在视频左下角或右下角的安全区域，优先选择人物较少的一侧，通常拆成两行，例如“山东”“济南”。使用蓝色/青色或白色配深色描边，画布字号 52–82px。不能自行编造地点，也不能把地点并入标题。

当存在两个以上文字角色时，至少使用两个不同 seed 的元素组合，例如主标题使用黄色粗描边组合、正文强调句使用红色组合。除非画面确实无法保证可读性，否则不能所有文字都使用同一种组合；如必须统一，要记录原因。不能临时添加元素库之外的颜色、字体、描边或阴影数值。

这些是版式角色，不是改写授权。模板字段必须逐字保留。原声模式下字幕来自模板文案或原声内容，不能生成替代旁白。最终检查必须确认角色顺序、至少两种视觉处理、没有过大的正文段落、对比度足够，以及地点独立显示。检查失败时先修改文字页面，再报告完成。

可复用的 HTML 实现样例位于 `references/html-text-layouts/README.zh-CN.md` 和
`references/html-text-layouts/original-audio-vertical.html`。复制其结构后，只替换为模板中的真实字段，并保留
`openfilm-text` JSON 结构，这样才可进入剪映草稿导出链路。普通任意 HTML/CSS 虽然可能在 Studio 中显示，但不能默认转换成剪映原生文字。

## 开始前检查

读取 OpenFilm 手册和现有工程。根据用户要求、现有工程或主素材确定画布尺寸、比例和帧率；不要默认使用 1080×1920 或 30fps。检查素材的真实时长、分辨率、旋转信息和声音，不根据文件名或首帧猜测内容。

只在执行当前命令确实需要了解素材时读取必要的素材信息，单纯修改文字样式不重新抽帧。修改后直接汇报结果。项目中保留 `ad-plan.json`，记录输入素材、句子、镜头范围、声音状态、文字页面、样式和实际输出状态。`film.html` 仍是可编辑工程。

## 镜头选择

将模板文案按标点和自然停顿拆成完整句子并分配稳定 ID。模板中已有文字是锁定原文，不能压缩、概括、改写、补写或删字。原声模式只把句子作为字幕/文字单元；开启旁白时，使用原生接口生成的真实音频与时间戳。不得改写、删减或截断句子；允许多句作为同一组文字同时呈现。

检查每个候选镜头的动作、构图、主体和真实时间范围。镜头必须与文字表达的内容相关，不能为了凑数量使用无关素材。保持正常播放速度；较长文字应使用多个相关镜头，而不是加速视频。

## 文字和可读性

生成文字前读取元素库和规则：

```sh
openfilm text-styles elements
openfilm text-styles generation-rules
```

元素库是文字外观的来源。每次生成分别从字体、文字颜色、描边颜色和描边宽度元素中抽取数值，再组合为剪映/CapCut 原生文字支持的外观。需要复现时使用稳定的 `--seed`；需要确认导出限制时读取 `rules`，不要添加元素库和兼容规范之外的字段。

每个文字元素优先读取当前剪辑模板的 `textStyleIds`。如果列表有内容，必须使用其中的样式 ID，通过 `openfilm text-styles page --preset <id>` 生成，不能使用未勾选的样式；如果列表为空，才省略 `--preset`，从元素库抽取生成。不同文字角色使用不同 seed，角色内部保持同一组解析后的元素。不要手写新的外观对象或随意调整未支持的参数；在 `ad-plan.json` 的 `textPage` 中记录 seed、抽取到的元素、解析后的外观和选择理由。文字和描边必须避开人物、器材和安全区域。

元素库只组合可导出为剪映/CapCut 原生文字的字段。不要把 `backgroundColor`、`backgroundOpacity`、`borderRadius`、阴影、任意 CSS、花字资源或 HTML 背景框加入原生文字页面；这些内容会触发渲染回退。优先使用结构化文字页面，使剪映导出保持可编辑；不支持的复杂效果必须记录降级原因。

## 构建和检查

视频原声默认保留在原视频片段内，通过视频片段的裁剪和音量控制，不单独拆出原声音轨；不要组合无声预览视频和分离的原声。只有用户明确要求分离音频或独立剪辑原声时才拆轨。文字、旁白和可选音乐使用各自轨道。原声模式不生成替代旁白。执行用户明确要求的检查时，才核对文字页面、镜头边界、音频、遮挡和原生文字状态。

只有用户明确要求时才导出 MP4 或剪映草稿。报告实际输出路径、样式选择、音频状态、无法完成的句子和导出兼容性。

默认执行链路：接收命令 → 执行命令 → 汇报结果。执行完成后直接汇报，不自动运行快速预览、完整检查、重复帧渲染或混音检测。仅在用户明确要求预览或检查时执行相应命令，并如实报告实际执行的范围。

## 文案与音频执行规则

请求旁白但 TTS 失败时必须报告未完成，保留成功素材供重试，不得静默跳过或使用其他服务。固定时长无法容纳全文朗读时报告冲突，不删字、不截断或擅自延长。
用户提供的标题、正文等成品文案完整逐字保留，不删减、不精简、不只用标题，不再询问是否保留全文。文案二创的 source 按用户当前指令执行，未指定方向时保留原意、优化表达，最终稿也必须完整使用。保持用户指定时长，通过文字分段、排布与节奏呈现全部文案，未开启朗读时不按虚构的配音时长限制文字；开启朗读则按真实时长编排。不要求用户在精简、仅标题、延长时长中选择；完成后如实汇报可读性局限，不擅自延长。

同一画面允许同时展示两句或多句文案，按语义分组、多行或多个文字块排布；不强制一句一屏，也不要求每句话独占时间段。短时长且文案较多时，优先让相关句子同屏呈现并为每组分配展示时间，完整保留文案和指定时长，避免遮挡主体。单行标题规则只限制单个标题，不限制同屏正文句数。

标题、多个副标题和正文文案应使用不同的文字填充色；同屏各文字块不要全部同色，应按角色和语义分配清晰可辨的不同颜色，并保证与画面对比度。优先选用用户所选样式中不同颜色的样式；若已选样式全同色，保留字体、描边等设置，允许调整填充色以满足分色要求，不因此停下询问。横向排版优先每个文字块单独占一行，按实际字体、组内最长句和画布可用宽度计算正文统一绝对像素字号，使每行尽量铺满可用宽度；正文按组内最长句计算统一字号，短句不单独放大，正文不得超过主标题字号。左右保留安全边距，不贴边、不裁字、不通过拉伸字形填满。允许同屏多句、多行，但不要把不同句子挤在同一行；保持完整文案和可读性。

文字实际行宽与人物避让规则：以渲染字体加载后的实际文字笔画宽度（包含描边、阴影）计算字号，不以 JSON 文本框宽度代替文字宽度，也不能只把文本框拉宽。无人物占用时，每行文字目标接近画布宽度的 90%，左右各留约 5% 安全边距；短标题应继续放大到接近目标行宽。正文优先在句间拆成多个独立文字块，每句各占一行，同组使用统一字号，避免一整个小字号段落只占画面局部。所有文字包括标题、副标题、正文、地点标签，其笔画、描边和阴影均不得覆盖人物的头部、身体、手脚和动作区域。位置根据所选镜头整个区间内人物活动范围决定，不只看首帧，不默认顶部或底部安全；先复用已有素材分析和帧缓存。人物避让优先于铺满行宽；没有足够横向空白时重新分组、调整位置或换用相关镜头，不为填满一行压住人物，也不缩成不可读的小字。此处是生成时布局依据，不追加生成后的完整预览检查。

独立小句排版规则：文案包含多个小句时，按逗号、分号、句号、问号、感叹号等自然停顿划分，保留词句和原文字序，画面文字去掉语句标点。每个小句必须是结构化文字 JSON 的独立 texts 元素，拥有独立 text、x、y、width、fontSize；不得将多个小句塞入一个 text 字符串或用换行符堆在同一个文本框里。每个小句只占一行，同组按最长句计算相同字号。相关小句可以在同一时间段内同屏纵向分层排列，位置和行间距按人物之外的空白区域独立设置，不必都挤在同一横向长条或固定底部区域。每行文字与描边不重叠，相邻小句使用可区分的颜色。人物避让优先；空白不足时将小句分成连续的同屏组呈现，完整使用全部文案并保持指定总时长，不删文案、不询问。

视频满画布优先规则：主视频画面必须铺满画布，不得为了给标题、地点或正文腾空间而缩小视频、把视频放在中间小窗口、增加黑底边框或上下留出文字专用黑区。保持原视频比例，用等比 cover 填充画布；必要时调整裁切位置以保留人物和完整动作，禁止非等比拉伸。文字必须叠加在满画布的视频上，通过移动位置、分别调整字号、拆分独立小句和分时分组展示来避开人物。任何文字排版规则都不能成为缩小主视频的理由。可用空间不足时减少同屏小句数量，在指定总时长内继续呈现全部文案；不得改为缩小视频的海报式布局。

画面文案去标点规则：原始输入和模板配置原样保存；生成标题、副标题、正文的 JSON texts[].text 时，先按原文标点划分小句，再移除用于语句表达的标点（逗号、句号、顿号、分号、冒号、问号、感叹号、引号、括号、书名号、省略号、破折号及对应英文标点），不在画面显示。词句和先后顺序完整保留，不得借去标点删减或改写内容。不同小句仍使用独立文字元素，不因去标点合成一个文字框。数值小数点、百分号、正负号、日期、网址、型号和专名中的必要符号按语义保留，避免改变事实。去标点后的文字用于测量字号、编辑预览和剪映导出，源 JSON 内不保留待显示的语句标点。此规则是全文保留规则的明确展示例外，优先于逐字保留标点的旧要求。

写入 film.html 时，iframe、video、audio、section 必须显式闭合，禁止 `<iframe ... />` 自闭合写法。完成前仅用本地 film-doc 的 readFilmFile 解析确认工程语法合法；不进行渲染或完整预览检查。语法错误先修复，不能报告影片已生成。

正文层级与间距规则：同组正文小句使用完全相同的 fontSize，以组内最长一行和可用区域计算统一字号，短句不得单独放大。所有副标题和正文的字号不得大于主标题；正文不为铺满宽度超过标题字号。按实际渲染后的文字、描边和阴影外接边界安排位置，正文相邻行之间保留统一字号约 8%–12% 的紧凑空白（按包含描边、阴影的实际边界计算），不留过大的段间空隙；标题、副标题、正文之间也不得相互覆盖。空间不足时减少同屏句数并分组分时展示，不叠字、不删文案、不缩小主视频。正文填充色必须与标题明显不同，避免同色和相近色，例如标题黄色时正文不得再选黄色、金色或相近橙色；优先选对比明确的白色、青色或其他不同色相，并结合视频背景保持清晰。此规则优先于每行单独放大铺满的旧要求。
